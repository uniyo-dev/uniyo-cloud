2.4. Data Value Chain

The Data Value Chain is introduced to describe the information flow within a big data system as a series of steps needed to generate value and useful insights from data. The Big Data Value Chain identifies the following key high-level activities:

2.4.1. Data Acquisition

Data Acquisition is the process of gathering, filtering, and cleaning data before it is put in a data warehouse or any other storage solution on which data analysis can be carried out. This is the very first step in the chain—without good data acquisition, the rest of the chain is built on a shaky foundation.

Challenges in Data Acquisition:

  • Infrastructure Requirements: The infrastructure required to support the acquisition of big data must deliver low, predictable latency in both capturing data and in executing queries. This means the system must be extremely fast and reliable.
  • High Transaction Volumes: The system must be able to handle very high transaction volumes, often in a distributed environment (where data is spread across many servers).
  • Flexibility: It must support flexible and dynamic data structures, as data comes in many forms (structured, semi-structured, and unstructured).

💡 Real World Example (Ethiopia - TeleBirr Transactions):

Every day, millions of TeleBirr transactions occur across Ethiopia. The Data Acquisition phase involves:

  • Gathering: Capturing every transaction (sender, recipient, amount, time, location) from thousands of agents and mobile users.
  • Filtering: Removing duplicate or incomplete records (e.g., transactions that timed out).
  • Cleaning: Correcting any errors, such as invalid phone numbers or mismatched currencies.
  • Infrastructure: The system must handle millions of transactions per day with almost zero downtime.

2.4.2. Data Analysis

Data Analysis is concerned with making the raw data acquired amenable to use in decision-making as well as domain-specific usage. Data analysis involves:

  • Exploring: Getting to know the data, its patterns, and its quirks.
  • Transforming: Changing the data into a format that is easier to analyze (e.g., normalizing values).
  • Modeling: Applying mathematical and statistical models to the data.

The Goal of Data Analysis: The ultimate goal is highlighting relevant data, synthesizing, and extracting useful hidden information with high potential from a business point of view.

Related Areas: Data analysis is the foundation for:

  • Data Mining: Discovering patterns in large datasets.
  • Business Intelligence: Using data to make strategic business decisions.
  • Machine Learning: Building algorithms that learn from data to make predictions.

💡 Real World Example (Ethiopia - Agricultural Data Analysis):

Ethiopia's Ministry of Agriculture collects data from weather stations and farmers. In the Analysis phase:

  • Exploring: Analysts look at historical rainfall data and crop yield data to find patterns.
  • Transforming: They convert raw temperature readings into "growing degree days" (a metric used to predict crop growth).
  • Modeling: They build a statistical model to predict the likelihood of drought in the upcoming season.
  • Result: The hidden information extracted is a drought warning that can help farmers plant drought-resistant crops or prepare irrigation.

2.4.3. Data Curation

Data Curation is the active management of data over its life cycle to ensure it meets the necessary data quality requirements for its effective usage. Data curation processes can be categorized into different activities such as:

  • Content creation: Generating new data or annotations.
  • Selection: Choosing which data is valuable and should be kept.
  • Classification: Organizing data into categories.
  • Transformation: Changing data formats to make them more useful.
  • Validation: Checking data for accuracy and completeness.
  • Preservation: Ensuring data is stored safely for the long term.

The Role of Data Curators: Data curation is performed by expert curators who are responsible for improving the accessibility and quality of data. Data curators (also known as scientific curators or data annotators) hold the responsibility of ensuring that data are:

  • Trustworthy
  • Discoverable (easy to find)
  • Accessible (easy to access)
  • Reusable
  • Fit their purpose

Key Trend: A key trend for the duration of big data utilizes community and crowdsourcing approaches—where the public or a community of experts helps to curate and validate data.

💡 Real World Example (Ethiopia - Community Data Curation):

In Ethiopia, a project mapping water sources in rural areas may use community crowdsourcing. Local citizens use a mobile app to report the location and status of wells. Data curators then:

  • Validate the entries by cross-referencing with satellite imagery.
  • Classify each water source as "active", "dry", or "contaminated".
  • Preserve this data so that NGOs and the government can use it for years to plan water infrastructure.

2.4.4. Data Storage

Data Storage is the persistence and management of data in a scalable way that satisfies the needs of applications that require fast access to the data.

Traditional vs. Big Data Storage:

  • RDBMS (Relational Database Management Systems): For nearly 40 years, these have been the main and almost unique solution to the storage paradigm. They use the ACID properties (Atomicity, Consistency, Isolation, Durability) to guarantee database transactions.
  • The Problem with RDBMS: ACID properties guarantee transactions, but they lack flexibility with regard to schema changes. The performance and fault tolerance of RDBMS suffer when data volumes and complexity grow, making them unsuitable for big data scenarios.
  • NoSQL Technologies: NoSQL technologies have been designed with the scalability goal in mind and present a wide range of solutions based on alternative data models. NoSQL databases can handle massive volumes of unstructured and semi-structured data with ease.
FeatureRDBMS (SQL)NoSQL (Big Data)
Data ModelRigid, tabular (rows and columns)Flexible (key-value, document, graph, column)
SchemaFixed schema requiredSchema-less or dynamic
ScalabilityVertical (scale up - expensive)Horizontal (scale out - distributed)
ACID ComplianceYes (Atomicity, Consistency, Isolation, Durability)No (prioritizes speed and availability over strict consistency)
Best ForComplex queries, structured dataBig data, real-time applications, unstructured data

💡 Real World Example (Ethiopia - Big Data Storage):

Commercial Bank of Ethiopia uses traditional RDBMS to store customer account details (structured, highly secure, ACID compliant). However, to analyze customer spending patterns from millions of ATM and POS transactions, they may use a NoSQL database (like HBase or MongoDB) to store the massive transaction logs, allowing for fast, scalable analysis without the overhead of rigid schemas.

2.4.5. Data Usage

Data Usage covers the data-driven business activities that need access to data, its analysis, and the tools needed to integrate the data analysis within the business activity.

Business Impact: Data usage in business decision-making can enhance competitiveness through:

  • Reduction of costs: Identifying inefficiencies and waste.
  • Increased added value: Creating new products, services, or features based on data insights.
  • Improved performance metrics: Any other parameter that can be measured against existing performance criteria.

💡 Real World Example (Ethiopia - Retail Data Usage):

A large supermarket chain in Addis Ababa uses the Data Value Chain to improve its business:

  • Acquisition: They collect point-of-sale (POS) data every time a customer buys an item.
  • Analysis: They analyze this data to find the most popular products and the busiest shopping times.
  • Curation: They clean the data to remove returns and errors.
  • Storage: They store it in a data warehouse.
  • Usage: The store manager uses the analyzed data to reduce costs (by ordering only the most popular items and reducing waste), increase added value (by offering personalized discounts to frequent shoppers), and improve performance (by scheduling more cashiers during peak hours).

📌 Cheat Notes: Key Points to Remember (Part 3)

  • Data Value Chain (5 Stages): Acquisition → Analysis → Curation → Storage → Usage.
  • Data Acquisition: Gathering, filtering, and cleaning data. Requires low latency and high transaction volume capacity.
  • Data Analysis: Exploring, transforming, and modeling data to extract hidden insights for decision-making.
  • Data Curation: Active management to ensure data is trustworthy, discoverable, accessible, and reusable.
  • Data Storage: RDBMS (ACID, rigid) vs. NoSQL (scalable, flexible) – NoSQL is better for big data.
  • Data Usage: Using data-driven insights to reduce costs, increase value, and improve business performance.
